Propagator#

class Propagator(primary_body: Spacecraft, state_vector: StateArray, tspan: EpochArray | Tuple[EpochArray, EpochArray], force_models: ForceModel | Sequence[ForceModel], base_frame: Frame | None = None, atol: float = 2.220446049250313e-14, rtol: float = 2.220446049250313e-14, integrator: Literal['DOP853', 'IAS15'] = 'DOP853', n_densifier: int | None = None, propagate_STM: bool = True, STM0=None, look_event: str | None = None, convert_to_original_frame: bool = False, mass_is_variable: bool = False, display_progress: bool = True, copy_force_models: bool = True, backward: bool = False)#

Bases: object

Scarabaeus interface to numerical propagation.

This class integrates the equations of motion for a given state \(\mathbf{x}\) over a specified timespan:

\[\begin{split}\dot{\mathbf{x}} = \mathbf{f}(\mathbf{x}, t), \qquad \mathbf{x} = \begin{bmatrix} \mathbf{r} \\ \dot{\mathbf{r}} \\ \mathbf{p} \end{bmatrix}\end{split}\]

where \(\mathbf{r}\) is position, \(\dot{\mathbf{r}}\) is velocity, and \(\mathbf{p}\) are dynamic/static parameters. When propagate_STM=True the State Transition Matrix \(\boldsymbol{\Phi}\) is propagated alongside the state via the variational equation:

\[\dot{\boldsymbol{\Phi}}(t, t_0) = \mathbf{A}(t)\,\boldsymbol{\Phi}(t, t_0), \qquad \boldsymbol{\Phi}(t_0, t_0) = \mathbf{I}\]

where \(\mathbf{A}(t) = \partial\mathbf{f}/\partial\mathbf{x}\) is the Jacobian of the dynamics.

Parameters:
primary_bodySpacecraft

Nominal “primary” object associated with the propagated state. Used for convenience and compatibility; individual force models may internally act on different objects or subsets of the state.

state_vectorStateArray

Initial state (position/velocity + parameters) at epoch = state_vector.epoch.

tspanEpochArray or tuple of two EpochArrays

Times at which the solution is requested. If given an EpochArray, solution will be computed at each time step. If given a tuple of two EpochArrays, solution will computed at time steps determined by the selected integrator.

force_modelsForceModel or list[ForceModel]

One or more pre-configured force model instances. Each will be initialized with the given state_vector and base_frame. This argument is required in the current interface.

base_frameFrame, optional

Frame in which dynamics are evaluated. Defaults to J2000 if None.

atol, rtolfloat, optional

Absolute/relative tolerances for the numerical integrator.

integratorstr, optional

Integration scheme identifier (e.g. "DOP853").

n_densifierint, optional

Number of sub-intervals each integration step is resampled into, using the integrator’s dense output. Defaults to 10; pass 1 to get the solver’s own steps unchanged.

It applies only when tspan is a (t0, tf) tuple, because that is the case in which the output sits on the integrator’s adaptive steps. Those steps grow long where the dynamics are quiet, and an SPK written on them leaves SPICE interpolating across wide gaps. The default puts nine extra epochs inside every step, so the output stays fine where the steps are short and coarse where they are long, without imposing one fixed interval over the whole arc. Note that it therefore returns about ten times as many epochs as the bare steps, which costs memory in the propagated states and STMs and size in any SPK written from them.

The extra epochs come from the solver’s interpolant, not from fresh integration: DOP853 carries a dedicated 7th-order dense output, so they cost no additional function evaluations beyond the ones dense_output already requires. The solver’s own step endpoints are reproduced exactly, making the densified grid a superset of the undensified one.

An EpochArray tspan already names every output epoch, and integrator="IAS15" builds no interpolant, so neither can be densified. Leaving n_densifier at its default in those cases simply does nothing; asking for a value explicitly raises Propagator.DensifierGridError or Propagator.DensifierIntegratorError, rather than silently ignoring what was asked for.

propagate_STMbool, optional

If True, propagate the state transition matrix. Not yet supported with integrator="IAS15", which integrates the state alone: that combination makes propagate() raise Propagator.IAS15STMError, so pass propagate_STM=False.

STM0np.ndarray, optional

Initial STM. If None, identity is used.

look_eventstr, optional

Placeholder for event handling (WIP).

convert_to_original_framebool, optional

If True, map results back to the original state frame after propagation.

mass_is_variablebool, optional

If True, treat mass as a dynamic state (used with thrust models).

display_progressbool, optional

If True, displays integration progress bar in the terminal. Defaults to True.

copy_force_modelsbool, optional

If True, creates deep copies of the provided force models to avoid side effects.

Notes

Typical usage sequence:

  1. Construct a StateArray (via StateDefinition).

  2. Construct one or more ForceModel instances (e.g. ForceModelTranslation) configured for the relevant objects.

  3. Pass the model(s) to Propagator, which will bind them to the provided state and frame via initialize_force_models.

  • force_models may be a single instance or a list, enabling multi-object or multi-model configurations.

  • Each provided force model must implement:

    • initialize_force_models(state_vector, base_frame, t0)

    • dynamics_mode_list (property)

    • the appropriate acceleration/partial APIs used by the propagator.

classmethod from_dict(data: dict) → Propagator#

Reconstruct a Propagator from a dict produced by to_dict().

The reconstructed Propagator reproduces the original setup: rebuilding it and calling propagate() yields the same propagated states. The single primary_body instance is reused as the owner of the matching state components so the spacecraft is not duplicated.

Parameters:
datadict

Serialized propagator configuration.

list_forces() → dict#

The forces acting on each integrated object, as readable labels.

Returns:
dict

Maps the name of every object whose position is integrated — the spacecraft and any celestial body propagated alongside it — to the labels of the forces its force model applies, in that model’s dynamics_mode_list order. Entries follow state order.

See also

scarabaeus.ForceModelTranslation.list_forces

The labels of one force model.

scarabaeus.MissionSequence.list_forces

The same listing, leg by leg.

Notes

The labels are those of list_forces() on the bound force models, so they reflect what acts during propagation rather than what was configured: the origin’s point-mass term reinstated next to a non-central harmonics field, the integrated bodies added to the third-body term, a harmonics truncation clamped by its file.

Examples

>>> prop.list_forces()
{'ORCCA': ['ThreeBodyGravity(SUN, MOON)', 'CannonballSRP', 'PointMassGravity(EARTH)'],
 'Moon': ['ThreeBodyGravity(SUN)', 'PointMassGravity(EARTH)']}

propagate(display_progress: bool | None = None) → None#

Propagates the state of the system using numerical integration.

This method integrates the ordinary differential equations (ODEs) that describe the system’s dynamics using the specified integration method. The integration is performed over the time span defined by the initial and final times of the system’s time vector.

Save this Propagator’s reproducible configuration to a JSON or pickle file.

The file can be reloaded with load() to reconstruct an equivalent Propagator. The on-disk format follows fmt ("json" or "pickle"); when fmt is None it is inferred from the file extension (.pkl or .pickle gives pickle, otherwise JSON). Returns the resolved path.

exception DensifierGridError#

Bases: ValueError

Raised when n_densifier > 1 is combined with a tspan that already names every output epoch.

exception DensifierIntegratorError#

Bases: ValueError

Raised when n_densifier > 1 is asked of an integrator that builds no dense output to resample from.

exception DensifierValueError#

Bases: ValueError

Raised when n_densifier is not a whole number of at least 1.

exception IAS15STMError#

Bases: NotImplementedError

Raised when propagate_STM=True is combined with integrator="IAS15", which integrates the state alone.

exception MissingScaleFactorModelError#

Bases: ValueError

Raised when the state holds a force-model scale factor (eta_srp, eta_thermal, eta_antenna) but no force model applies it, so it would be estimated with a zero partial.
