ForceModelTranslation#

class ForceModelTranslation(primary_body: Spacecraft, t0: EpochArray | float = None, third_bodies: list | None = None, cannonball_SRP: bool = False, nplate_SRP: bool = False, sph_harm: bool = False, sph_harm_body: CelestialBody | None = None, sph_harm_order: int | None = None, sph_harm_cs_file: str | None = None, sph_harm_norm_flag: bool | None = None, sph_degree_max: int = 100, sph_harm_bodies: list | None = None, finite_burn: bool = False, maneuver: Maneuver | None = None, smoothed_maneuvers: list | None = None, dv_smoothing_factor: float = 1.0, yarkovsky_effect: bool = False, thermal_radiation: bool = False, thermal_model=None, antenna_radiation_pressure: bool = False, antenna_emitters: list | None = None, first_order_gauss_markov: bool = False, fogm_beta: ndarray | float | None = None, fogm_frame: str = 'inertial', fogm_body_fixed_frame=None, fogm_relative_body=None, piecewise_first_order_gauss_markov: bool = False, pfogm_beta: ndarray | float | None = None, pfogm_batch_length: float | None = None, pfogm_n_batches: int | None = None, pfogm_frame: str = 'inertial', pfogm_body_fixed_frame=None, pfogm_relative_body=None, fourier_acceleration: bool = False, fourier_degree: int = 0, fourier_frame: str = 'inertial', fourier_angle: str = 'time', fourier_period: float | None = None, fourier_body_fixed_frame=None, fourier_relative_body=None, fourier_coefficients: ndarray | None = None, piecewise_polynomial: bool = False, ppoly_order: int | None = None, ppoly_batch_length: float | None = None, ppoly_n_batches: int | None = None, ppoly_coefficients: ndarray | None = None, ppoly_frame: str = 'inertial', ppoly_body_fixed_frame=None, ppoly_relative_body=None, polyhedral_gravity: bool = False, polyhedron_shape=None, polyhedron_faces: ndarray | None = None, polyhedron_density=None, polyhedron_gm=None, polyhedron_body_fixed_frame=None, polyhedron_scale: float = 1.0, custom_models: list | None = None)#

Bases: ForceModel

High-level translational dynamics force model.

This class aggregates and manages all translational (i.e., orbital) force contributions acting on a spacecraft — such as point-mass gravity, spherical harmonics, solar radiation pressure, and thrust — into a single, configurable interface. It acts as the physical backbone of trajectory propagation and estimation in Scarabaeus.

The total translational acceleration is the ordered sum of all active sub-models:

\[\mathbf{a}_\text{total} = \mathbf{a}_\text{grav} + \mathbf{a}_\text{3b} + \mathbf{a}_\text{SRP} + \mathbf{a}_\text{thrust} + \mathbf{a}_\text{Yark} + \mathbf{a}_\text{FOGM} + \cdots\]

where each term is non-zero only when the corresponding flag is enabled at construction time.

Unlike low-level force model components (e.g., PointMassGravity, CannonballSRP), this class serves as a meta-model: it does not compute accelerations itself, but dynamically instantiates and combines sub-models according to the selected configuration flags.

Parameters:
primary_bodySpacecraft

The primary spacecraft object to which the forces are applied. Contains physical properties such as mass, area, and reflectivity.

t0EpochArray or float, optional

The initial epoch for the force model. Sub-models that are bound to a propagation leg (ephemeris caching windows, impulsive burns) use the leg’s own start epoch instead, supplied by Propagator when it binds the model. This value is kept as configured and is what anchors the batch grid of PiecewiseFirstOrderGaussMarkov and PiecewisePolynomialAcceleration, which is required for those models and must be the same epoch for every leg of a MissionSequence.

third_bodieslist of CelestialBody, optional

List of bodies to be used in computing third body accelerations. SPICE-defined body positions are queried by EphemerisCache.

cannonball_SRPbool, optional

Enable a classical cannonball solar radiation pressure model. Ignored if nplate_SRP=True.

nplate_SRPbool, optional

Enable a multi-facet (n-plate) SRP model. Takes precedence over cannonball_SRP.

polyhedral_gravitybool, optional

Enable constant-density polyhedral (shape-model) gravity for the propagation origin. Replaces the default point mass, since a shape model already carries the body’s whole field.

polyhedron_shapestr or Path or object or np.ndarray, optional

The body’s shape: a path to a Wavefront .obj or an ASCII vertex/facet table, any object exposing vertices and faces, a (vertices, faces) pair, or a vertex array paired with polyhedron_faces.

polyhedron_facesnp.ndarray, optional

Facet indices, needed only when polyhedron_shape is a bare vertex array.

polyhedron_densityfloat or ArrayWUnits, optional

Bulk density in kg/km^3. Supply this or polyhedron_gm.

polyhedron_gmfloat or ArrayWUnits, optional

Gravitational parameter in km^3/s^2; the density follows from the mesh volume.

polyhedron_body_fixed_framestr or Frame, optional

Frame the mesh is expressed in, rotated through SPICE each evaluation.

polyhedron_scalefloat, optional

Multiplier taking the shape file’s length unit to km.

sph_harmbool, optional

Enable a spherical harmonics gravity field expansion. On its own it only turns harmonics on; the fields may be named either by the singular keywords below or by sph_harm_bodies.

sph_harm_bodyCelestialBody, optional

The celestial body for which the spherical harmonics are defined. Optional when the fields are listed in sph_harm_bodies instead.

sph_harm_orderint, optional

The maximum harmonic order (m) to include.

sph_harm_cs_filestr, optional

Path to the coefficient file containing Cnm/Snm terms.

sph_harm_norm_flagbool, optional

Whether the coefficients are normalized (True) or unnormalized (False).

sph_degree_maxint, optional

The maximum spherical harmonic degree (n) to include. Default is 100.

sph_harm_bodieslist of dict, optional

Harmonic fields, for flying somewhere several bodies have one — Jupiter and its moons, say. Each entry is a dict with body, order and cs_file, optionally norm_flag (default True) and degree_max (default 100). List every field here, central body included, and leave the singular keywords out:

sph_harm=True,
sph_harm_bodies=[
    {"body": jupiter, "order": 8, "cs_file": jup_cs},
    {"body": io,      "order": 2, "cs_file": io_cs},
]

A field named by the singular keywords is simply the first field, so the two spellings compose and an existing single-field model can gain a second body without its first being rewritten. One field per body: two fields for the same body would count that body’s gravity twice and are refused. Each field’s Cnm/Snm, GM and pole partials are keyed by its own body, so several fields can be estimated at once.

finite_burnbool, optional

Enable continuous-thrust (finite burn) modeling.

maneuverManeuver, optional

Maneuver definition object for finite-burn or impulsive dynamics.

yarkovsky_effectbool, optional

Enable Yarkovsky effect modeling.

thermal_radiationbool, optional

Enable the recoil of the heat the spacecraft radiates, scaled by the estimable eta_thermal. Requires thermal_model.

thermal_modeldict or str, optional

Temperature tables and radiating surfaces, or the path of a JSON file holding them; see ThermalRadiation.

antenna_radiation_pressurebool, optional

Enable the recoil of the power the spacecraft transmits (radio antennas, LIDAR), scaled by the estimable eta_antenna. Requires antenna_emitters.

antenna_emitterslist of dict, optional

The emitters; see AntennaRadiationPressure.

piecewise_polynomialbool, optional

Enable a deterministic empirical acceleration that is a polynomial in time over each batch of a fixed grid anchored at t0; see PiecewisePolynomialAcceleration. Its coefficients are estimated through a static a_ppoly state entry. May be combined with the Gauss-Markov and Fourier models.

ppoly_orderint, optional

Polynomial order within a batch, required when piecewise_polynomial is on: 0 for a zero-order hold (one constant acceleration per batch, 3 * ppoly_n_batches coefficients) or 1 for a first-order hold (linear per batch and continuous across batches, 3 * (ppoly_n_batches + 1) node values).

ppoly_batch_lengthfloat, optional

Duration of each batch, in seconds.

ppoly_n_batchesint, optional

Number of batches.

ppoly_coefficientsnp.ndarray, optional

Coefficients applied when the state carries no a_ppoly entry, to use the model as a known force without estimating it.

fogm_frame, pfogm_frame, ppoly_framestr, optional

Frame the components of the first-order Gauss-Markov, piecewise Gauss-Markov and piecewise polynomial accelerations are expressed in, as fourier_frame is for the Fourier one: "inertial" (the propagation frame, the default), "RTN" (radial / along-track / cross-track, the RTN triad) or "body_fixed".

fogm_body_fixed_frame, pfogm_body_fixed_frame, ppoly_body_fixed_framestr or Frame, optional

Frame the components are expressed in, for a "body_fixed" frame (for example 'IAU_BENNU').

fogm_relative_body, pfogm_relative_body, ppoly_relative_bodystr or Body, optional

Body the RTN triad is built about, when that is not the propagation origin.

custom_modelslist of CustomDynamicModel, optional

User-defined force models built in a script. Their accelerations are summed with the built-in ones, and the CustomParameter objects they declare are propagated, differentiated, and estimated like any built-in solve-for parameter — so a new force needs no change to the library source.

Notes

The constructor defines which physical models are active and stores all metadata (files, degrees, body references, etc.) needed for later use. Actual sub-model objects are not built until initialize_force_models() is called, which binds the model to a specific StateArray, reference frame, and epoch.

When both SRP flags are False, SRP effects are excluded entirely. If spherical harmonics are not activated, a baseline point-mass gravity model is always included.

Examples

Create a force model with third body perturbations.

>>> import scarabaeus as scb

>>> sc = scb.Spacecraft('EXAMPLE SC', -123)     # example spacecraft

>>> sun, venus, moon, mars = scb.CelestialBody.from_constants(['sun', 'venus', 'moon', 'mars'])
>>> third_bodies = [sun, venus, moon, mars.barycenter()]
>>> fm = scb.ForceModelTranslation(primary_body = sc, third_bodies = third_bodies)

Add a user-defined force with its own estimated parameter, without touching the library source.

>>> k = scb.CustomParameter("thermal_k", default=1.0)
>>> def thermal(position, params):
...     r = np.linalg.norm(position)
...     return params["thermal_k"][0] * 1e-12 * position / r
>>> fm = scb.ForceModelTranslation(
...     primary_body = sc,
...     custom_models = [scb.CustomDynamicModel("Thermal", thermal, parameters=[k])],
... )

list_forces() → list[str]#

Readable labels of the forces this model applies to primary_body.

One label per entry of dynamics_mode_list, in that order. A label is the sub-model’s class name followed, in parentheses, by what tells one configuration of that model from another: the origin of the point-mass term, the bodies the third-body term attracts with, the field body and truncation of a spherical-harmonics term, the name of a custom model, and so on.

Returns:
list of str

For example ['ThreeBodyGravity(SUN, MOON)', 'CannonballSRP', 'PointMassGravity(EARTH)'].

See also

scarabaeus.Propagator.list_forces

The same listing for every integrated object.

scarabaeus.MissionSequence.list_forces

The same listing, leg by leg.

Notes

Before initialize_force_models() has run (i.e. before the model is handed to a Propagator) the labels describe the configuration as passed to the constructor; details that only the propagation fixes, such as the origin, are left out. Once bound, the labels come from the live sub-models and can differ from the configuration:

  • PointMassGravity is added at binding when spherical-harmonics fields are configured but none is centred on the propagation origin, so the origin keeps its monopole.

  • ThreeBodyGravity lists the bodies that actually attract: a third body that also carries a harmonics field is dropped (the field already includes its monopole), and every celestial body integrated in the state is added whether or not it was in third_bodies.

  • A spherical-harmonics truncation is clamped to the maximum degree of its coefficient file.

to_dict() → dict#

Serialize the force-model configuration to a JSON-friendly dict.

Captures the constructor options needed to rebuild this model. primary_body is intentionally omitted: it is owned by the Propagator and re-supplied to from_dict() (a file written by save() carries it alongside). t0 is the epoch the model was configured with, which anchors the PFOGM batch grid and the Fourier phase; binding to a leg does not change it. Maneuver objects and custom models cannot be serialized (both hold user callables); only their presence is recorded.

Returns:
dict

The constructor options, readable by from_dict().

A force model was asked for a body’s acceleration under its own gravity field.

Raised when sph_harm_body names the same body as primary_body: the harmonic expansion would be evaluated at zero separation, and the physical answer — a body exerts no net force on itself — is not what that configuration computes.
