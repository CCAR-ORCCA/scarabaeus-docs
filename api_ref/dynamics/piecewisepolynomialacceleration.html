PiecewisePolynomialAcceleration#

class PiecewisePolynomialAcceleration(origin: Body, spacecraft: Spacecraft, base_frame: Frame, t0: EpochArray | float, batch_length: float, n_batches: int, order: int, coefficients: ndarray | None = None, frame: str = 'inertial', body_fixed_frame=None, relative_body=None)#

Bases: DynamicModel

Models an empirical acceleration as a piecewise polynomial in time over a fixed batch grid.

The arc is divided into \(N_b\) batches of length \(L\) starting at \(t_0\), exactly as in PiecewiseFirstOrderGaussMarkov. Within batch \(k\), with the local time \(\tau = (t - t_0 - kL)/L \in [0, 1]\), the acceleration is a polynomial of the chosen order:

order=0 (zero-order hold)

One constant 3-vector per batch,

\[\mathbf a(t) = \mathbf c_k ,\]

which jumps at the batch boundaries.

order=1 (first-order hold)

One 3-vector per batch boundary (node), linearly interpolated in between,

\[\mathbf a(t) = (1 - \tau)\,\mathbf n_k + \tau\,\mathbf n_{k+1} ,\]

so the acceleration is continuous across batches by construction: the end of batch \(k\) and the start of batch \(k+1\) share the node \(\mathbf n_{k+1}\).

The coefficients are components in the frame chosen with frame, and the applied acceleration is \(\mathbf T\,\mathbf a(t)\), where \(\mathbf T\) rotates that frame into the propagation frame.

Unlike the Gauss-Markov models, nothing here is integrated: the coefficients are constants of the dynamics, estimated as a 'static' parameter. The acceleration is linear in them, so the partial the filter needs is the interpolation matrix itself,

\[\begin{split}\frac{\partial \mathbf a}{\partial \mathbf c} = \begin{cases} [\,\mathbf 0 \;\cdots\; \mathbf I_3 \;\cdots\; \mathbf 0\,] & \text{order } 0 \\ [\,\mathbf 0 \;\cdots\; (1-\tau)\mathbf I_3 \;\; \tau\mathbf I_3 \;\cdots\; \mathbf 0\,] & \text{order } 1 \end{cases}\end{split}\]

which is exact rather than a difference approximation.

Notes

The estimated state is one stacked ("a_ppoly", spice_id) entry, ordered batch-major (order=0) or node-major (order=1):

order 0:  [ c0_x c0_y c0_z | c1_x c1_y c1_z | ... | c(N-1)_x ... ]   3*N
order 1:  [ n0_x n0_y n0_z | n1_x n1_y n1_z | ... | nN_x     ... ]   3*(N+1)

with \(N\) the number of batches. coefficient_labels() returns the matching names. The state vector must contain an entry of the form

  • ('a_ppoly', n_coefficients, 'estimated', 'static', owner, value)

for the coefficients to be estimated.

Batch membership follows the PFOGM convention: interior boundaries belong to the batch that starts there, and the closing endpoint belongs to the last batch. The propagator splits its arcs at the batch boundaries and pins each arc to its batch with pin_batch_window(), so the zero-order hold’s jump never falls inside an integration step.

In the "RTN" frame the coefficients are radial, along-track and cross-track components, and the coefficient partial above is left-multiplied by \(\mathbf T\). The RTN triad is built from the state, so the acceleration also gains the position and velocity partials frame_partials() returns; the inertial and body-fixed rotations depend on the epoch alone.

Examples

A first-order hold over four one-day batches, estimated:

import scarabaeus as scb

state = [
    ("position", 3, "estimated", "dynamic", sc, [7000, 0, 0]),
    ("velocity", 3, "estimated", "dynamic", sc, [0, 7.5, 0]),
    ("a_ppoly", 15, "estimated", "static", sc, [0.0] * 15),
]

force_model = scb.ForceModelTranslation(
    primary_body=sc,
    t0=arc_start,
    piecewise_polynomial=True,
    ppoly_order=1,
    ppoly_batch_length=86400.0,
    ppoly_n_batches=4,
)

pin_batch_window(t_start: float, t_end: float) → int | None#

Pin the batch that owns an integration arc, so the dynamics stay continuous across it.

Batch membership is right-continuous, so the epoch closing an arc that ends on a batch boundary belongs to the next batch. For a zero-order hold the acceleration jumps there; for a first-order hold its slope does. Either way an integrator evaluating its final stage on the boundary sees a discontinuity at the very point it has to land on. Pinning the batch for the arc removes it from the arc’s interior and endpoint alike.

Only arcs that lie within a single batch are pinned; the propagator already splits arcs at interior batch boundaries, so that is the normal case. Anything else clears the pin and leaves the per-epoch lookup in charge.

Parameters:
t_start, t_endfloat

Arc bounds in ephemeris seconds (TDB); order does not matter.

Returns:
int or None

The pinned batch index, or None if the arc was not pinned.
