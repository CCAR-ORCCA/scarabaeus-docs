CustomFilter#

class CustomFilter(propagator: Propagator | MissionSequence, measurements: MeasurementSpec, settings: FilterSettings, estimator=None, smoother=None, traj_name: str | None = None, traj_dir: str | None = None, overwrite_traj: bool = True, verbose: bool = True)#

Bases: FilterOD

Estimator whose whole algorithm is supplied from a script.

CustomFilter completes the trio started by CustomDynamicModel and CustomMeasurement. Where those replace one model, this replaces the estimator itself: the user writes the estimation algorithm and Scarabaeus provides the scaffolding around it — reference trajectory, measurement timeline, residuals and partials, state-transition matrices, process noise, and the SolutionOD packaging that the rest of the toolchain consumes.

Unlike LKF or SRIF, nothing here assumes a particular estimator structure. The algorithm is free to be

  • sequential — any Kalman/information/square-root recursion,

  • batch — accumulate normal equations over all epochs and solve once,

  • sigma-point (UKF/CKF) — propagate sigma points through the real nonlinear dynamics and measurements with predict() and predict_measurements(),

  • Gaussian mixture — run any of the above per component and recombine,

  • polynomial chaos — evaluate the model at the quadrature/collocation nodes and fit the expansion,

  • sampling (MCMC, particle) — score candidate states by their measurement likelihood.

The estimator is a callable invoked once per fit() iteration. It receives the filter itself — the toolkit below — and returns the histories the solution is built from.

Notes

Residuals and partials returned by measurement_block() are computed against the current reference trajectory, and fit() re-linearises about the updated reference between iterations. An estimator that works in absolute states rather than deviations should use predict() and predict_measurements() instead.

Those two run a full propagation (and, for the second, a full measurement pass) per call. A sigma-point filter therefore costs 2n+1 of them per iteration — acceptable offline, but it is the dominant cost, so cache aggressively inside the estimator.

Examples

A sequential Kalman recursion written from scratch:

import numpy as np
import scarabaeus as scb

def sequential(filter):
    P = filter.initial_covariance_matrix
    x = filter.initial_deviation
    deviations, covariances = [], []

    previous = None
    for epoch in filter.timeline:
        if previous is not None:                      # time update
            Phi = filter.stm_between(previous, epoch)
            x, P = Phi @ x, Phi @ P @ Phi.T
        previous = epoch

        block = filter.measurement_block(epoch)
        if block is not None:                         # measurement update
            H = block["partials"][:, : filter.n_states]
            R = filter.measurement_covariance(block["sigma"], epoch)
            S = H @ P @ H.T + R
            K = P @ H.T @ filter.safe_inv(S)
            x = x + K @ (block["residuals"] - H @ x)
            P = (np.eye(filter.n_states) - K @ H) @ P

        deviations.append(x)
        covariances.append(P)

    filter.record(deviation=deviations, covariance=covariances)

od = scb.CustomFilter(prop, measurements, settings, estimator=sequential)
solution, n_iterations, converged = od.fit(max_iterations=3)

A batch least-squares estimator over the same scaffolding:

def batch(filter):
    n = filter.n_states
    information = filter.safe_inv(filter.initial_covariance_matrix)
    normal = np.zeros((n, 1))

    for epoch in filter.measurement_epochs:
        block = filter.measurement_block(epoch)
        H = block["partials"][:, :n] @ filter.stm(epoch)
        W = filter.safe_inv(filter.measurement_covariance(block["sigma"], epoch))
        information += H.T @ W @ H
        normal += H.T @ W @ block["residuals"]

    P0 = filter.safe_inv(information)
    x0 = P0 @ normal

    deviations, covariances = [], []
    for epoch in filter.timeline:
        Phi = filter.stm(epoch)
        deviations.append(Phi @ x0)
        covariances.append(Phi @ P0 @ Phi.T)

    filter.record(deviation=deviations, covariance=covariances)

predict(initial_state, epochs=None)#

Propagate an arbitrary initial state through the real dynamics.

This is the escape hatch from the linearisation: sigma-point, mixture, chaos and sampling estimators need the nonlinear flow, not Phi.

Parameters:
initial_statearray_like

Initial state values, shape (n,), in the reference state’s own order and units.

epochsEpochArray, optional

Epochs to report. Defaults to the propagator’s own span.

Returns:
numpy.ndarray

Propagated states, shape (len(epochs), n).

Notes

Each call runs a full propagation; cache the results inside the estimator rather than calling it per epoch.

predict_measurements(initial_state, epochs=None) → dict#

Computed measurements for an arbitrary initial state.

Propagates initial_state and evaluates every configured measurement model along the resulting trajectory, giving \(h(x)\) without any linearisation.

Parameters:
initial_statearray_like

Initial state values, shape (n,).

epochsEpochArray, optional

Epochs to evaluate at. Defaults to the propagator’s own span.

Returns:
dict

Mapping of dataset name to the computed measurements.

Notes

This is the most expensive call in the toolkit: one propagation plus a full measurement pass. A sigma-point filter needs 2n+1 per iteration.
